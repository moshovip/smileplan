# Инструкция для ИИ-агента, работающего с этим репозиторием

Прочитайте этот файл целиком до первого действия.

## Что это за проект

Стоматологическая клиника, 12 кабинетов, МИС «Инфодент». Врач-хирург вместе с
заместителем главного врача внедряют разбор первичных консультаций: запись с
микрофона в кабинете, расшифровка с разделением говорящих, автоматическая
оценка по чек-листу клиники.

Пилот — 4 кабинета, два сильных врача и два слабых, чтобы был виден разброс.

## Главные ограничения — нарушать нельзя

1. **Данные о здоровье пациентов не покидают разрешённый контур.**
   Запрещено предлагать или использовать зарубежные сервисы (OpenAI, Anthropic,
   Google и любые другие вне РФ) для обработки записей и расшифровок консультаций.
   Допустимо: локальная обработка в клинике, российский GigaChat или SaluteSpeech
   по договору поручения, аренда сервера в ЦОД на территории РФ.
2. **Решение всегда за врачом.** Система не ставит диагнозов, не выносит клинических
   суждений и ничего не записывает в МИС без подтверждения человеком.
3. **Оценка без цитаты не ставится.** Каждая отметка в разборе сопровождается
   цитатой из расшифровки и таймкодом. Нет цитаты — нет отметки.
4. **Разборы не влияют на оплату и аттестацию врачей.** Это условие, на котором
   врачи согласились участвовать.
5. **Записываются только консультации.** Лечебные приёмы не записываются.

## Как устроены чек-листы

- `02-checklists/source-checklist-26.md` — исходник клиники, менять нельзя, это
  документ организации.
- `02-checklists/criteria.json` — машинная версия для ИИ. Её можно и нужно
  улучшать по результатам калибровки.
- Расхождение между ними допустимо только там, где оно объяснено в
  `02-checklists/criteria-notes.md`.

## Формат работы

Материалы — markdown и json. Никаких закрытых форматов.
Персональные данные пациентов в репозиторий не попадают: здесь только методика,
критерии и инструкции. Примеры консультаций — только выдуманные или обезличенные.
