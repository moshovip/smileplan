## Задача

Сейчас процедура в смете добавляется только кликом по зубу и жёстко привязана
к одному зубу (`item.toothId`). Профгигиена, снимок, наркоз, съёмный протез,
шинирование, кюретаж сегмента - всё это не привязано к одному зубу, и внести
их в смету нельзя.

Нужно: процедура может относиться к зубу, к нескольким зубам, к сегменту
(секстанту), к квадранту, к челюсти или ко всей полости рта.

## Что уже работает в нашу пользу

- `item.toothId` уже допускает `null`: голосовой ввод кладёт `toothId: null`,
  таблица рисует `'—'`, PDF фильтрует через `.filter(Boolean)`.
  То есть процедуры без зуба модель уже терпит - их просто нечем создать.
- Данные лежат в IndexedDB внутри `plan.items` как свободный JSON.
  Схему БД (`DB_VERSION`) поднимать не нужно, миграция - только нормализация
  при чтении.

## Модель данных

К элементу сметы добавляются два поля:

```js
{
  scope: 'tooth' | 'teeth' | 'sextant' | 'quadrant' | 'jaw' | 'mouth',
  toothIds: [16, 17],   // список FDI, пустой для 'mouth'
  toothId: 16,          // ОСТАВЛЯЕМ: первый из toothIds или null
  scopeLabel: 'Секстант 1',  // человекочитаемая подпись, считается при добавлении
  ...
}
```

`toothId` остаётся ради обратной совместимости: старые сметы, RoadmapModal
и промпт Groq продолжают работать без правок.

Нормализатор при чтении старой сметы:

```js
function normalizeItem(it) {
  if (it.scope) return it
  return { ...it, scope: it.toothId ? 'tooth' : 'mouth',
           toothIds: it.toothId ? [Number(it.toothId)] : [] }
}
```

### Справочник областей

| scope | Что это | toothIds |
|---|---|---|
| `tooth` | один зуб | `[16]` |
| `teeth` | произвольная группа | `[14,15,16]` |
| `sextant` | секстант (6 штук) | все зубы секстанта |
| `quadrant` | квадрант (4 штуки) | все зубы квадранта |
| `jaw` | челюсть | 16 зубов |
| `mouth` | полость рта | `[]` |

Секстанты по FDI:
S1 `18-14`, S2 `13-23`, S3 `24-28`, S4 `38-34`, S5 `33-43`, S6 `44-48`.

Квадранты: `1x`, `2x`, `3x`, `4x`. Челюсти: верхняя `1x+2x`, нижняя `3x+4x`.

Константы кладём в новый файл `src/data/toothScopes.js` - там же
`scopeLabel(scope, toothIds)` и `teethOfScope(scope, key)`.

## Прайс: область по умолчанию

В `priceItem` добавляется `defaultScope` (по умолчанию `'tooth'`).
Гигиена, отбеливание, снимок - `'mouth'`; кюретаж - `'sextant'`.
При выборе услуги в модалке область подставляется сама, но её можно поменять.

В форме услуги на странице Прайса появляется селект «Область по умолчанию».
Существующим 39 услугам проставляем `'tooth'` при чтении (нормализация),
дефолты для новых - в `data/defaultPriceList.js`.

## UI

### 1. Кнопка «+ Процедура» над таблицей процедур

Сейчас единственный вход - клик по зубу. Добавляем кнопку рядом с заголовком
«Процедуры»: открывает ту же модалку, но начинает с выбора области, а не с зуба.

### 2. Модалка процедуры: шапка с выбором области

Вместо статичного «Зуб 47 — процедура» - строка табов:

```
[ Зуб ] [ Неск. зубов ] [ Сегмент ] [ Челюсть ] [ Полость рта ]
```

- клик пришёл с зуба → активен «Зуб», номер подставлен;
- «Неск. зубов» / «Сегмент» → под табами мини-карта для выбора;
- «Челюсть» → две кнопки, «Полость рта» → ничего выбирать не надо.

### 3. ToothMap: мультивыбор

Компонент получает необязательные пропсы `selection` и `onSelectionChange`.
Когда они переданы - клик по зубу не открывает модалку, а переключает зуб
в наборе. Одиночный режим (текущее поведение) остаётся дефолтом, чтобы
не сломать RoadmapModal и карточку пациента.

Группировка `byTooth` переезжает с `item.toothId` на `item.toothIds`,
процедуры со `scope: 'mouth'` в карту не попадают.

### 4. Таблица процедур

Колонка «Зуб» → «Область». В ячейке:
- `tooth` - номер как сейчас;
- `teeth` - `16,17` (при >3 зубах `16,17,+2`, полный список в `title`);
- `sextant`/`quadrant`/`jaw` - подпись («Секстант 1», «Верхняя челюсть»);
- `mouth` - «Полость рта».

Ширину колонки увеличить, на мобильном - перенос.

### 5. Процедуры вне карты

Под картой зубов - блок «Общие процедуры» со списком того, что не привязано
к конкретным зубам, чтобы врач видел их и не терял.
